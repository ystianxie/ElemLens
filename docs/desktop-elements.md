# 桌面元素捕获与校验（第一版）

桌面工作区完成「捕获 → 编辑条件 → 重新查询与高亮 → 复制 Python / 导出 JSON」。
支持 Windows 的 UIA、Win32 后端，默认 UIA；后端由用户明确选择。
校验只读取当前控件，不执行点击、输入等试操作。

## 环境与使用

在「设置」配置桌面 Python 路径。留空时沿用网页功能的 Python 路径，但分别检测依赖。
该环境需要安装独立运行库，且包含本次新增的 Desktop.query()：

~~~powershell
python -m pip install D:\Project\DesktopAutomation
~~~

本机已验证环境为 D:\Project\DesktopAutomation\.venv\Scripts\python.exe。
不要求该环境安装 DrissionPage；网页环境也不要求安装桌面运行库。

1. 切换到左侧「桌面元素」，选择 UIA 或 Win32，检测环境。
2. 点击「开始捕获」，切换到目标软件。移动鼠标查看边框，Ctrl＋左键锁定，Esc 取消。
   捕获的鼠标按下和抬起都会被拦截；普通点击正常通过。捕获结束不主动切回觅元。
3. 也可搜索窗口、选择窗口并按需展开控件树。没有自动遍历整个桌面。
4. 分别编辑窗口条件和元素路径：勾选字段、修改值、切换标题/名称正则，删除不必要的祖先层。
   路径各层采用运行库的后代查询语义。
5. 点击「校验并高亮」：0 个、唯一、多个匹配分别展示。多匹配需选择具体结果查看高亮。
   唯一匹配仍需核对实际属性与边框，不能证明业务目标一定正确。
6. 复制 Python 定位代码，或导出 JSON 后在生产脚本中使用：

~~~python
from desktop_automation import Desktop

with Desktop() as desktop:
    element = desktop.ele(r"D:\elements\search.json")
    # 后续动作由自己的脚本明确调用。
~~~

JSON 使用运行库已有的 Locator version=1 格式，保留 metadata；导入按文件的 backend 切换。
候选条件使用进程名、窗口标题、类名及控件稳定属性，不自动写入 PID、句柄、运行时 ID、坐标。
缺少区分属性时保留捕获快照和原因，需补齐条件后校验。
最近 30 条捕获历史仅在本次会话保留，包括编辑草稿；历史属性是快照，校验始终重新查询。
修改条件立即清除旧校验结果。

## 结果与错误

- 0 个匹配：条件有效，但当前没有结果。
- 唯一匹配：显示当前属性，尝试高亮；隐藏、无矩形或完全在显示器外的控件说明原因。
- 多个匹配：显示实际总数，最多列出前 200 条；不默认选第一个。
- 窗口歧义：先缩小窗口条件，不能把多个窗口下的元素合并为成功。
- 无效正则、不支持字段、访问失败、控件失效、超时分别显示实际错误。
- 工作进程退出或超时会取消捕获并释放高亮，可点击「检测环境」重新启动。

## 实现边界

- src/useDesktop.ts、DesktopWorkspace.tsx：独立桌面状态、条件编辑、懒加载树、历史与结果。
- src-tauri/src/desktop_native.rs：原生鼠标/键盘钩子及四条不抢焦点、可穿透的高亮边框。
  钩子只记录坐标和拦截事件，控件读取在钩子外进行。
- src-tauri/src/desktop.rs、desktop_job.rs：按需启动隐藏 Python，JSONL 标准输入输出通信，
  12 秒请求超时，Windows Job Object 管理整组子进程，包括虚拟环境启动的下一级解释器。
- src-tauri/python/desktop_adapter.py：专用进程主线程拥有 COM/UIA 对象，负责坐标取控件、属性与层级。
  窗口枚举先用轻量 Win32 接口，UIA 在选中窗口时才打开；元素识别不会静默切换后端。
- 独立运行库只新增 Desktop.query(locator, timeout=0) -> list[dict]，复用已有查询规则。
  无匹配返回空列表，重复元素保留，窗口歧义仍抛错；不包含捕获、树或高亮界面。

会话代次、捕获会话与编辑版本用于丢弃迟到结果。切换工作区/后端、取消捕获、关闭程序会清理钩子与边框。
桌面适配层不调用网页 DrissionPage 适配器，不使用 CSS、XPath、frame，也不增加服务端口。
本版没有 OCR、图像定位、流程运行器或持久化元素仓库。

## 悬停延迟优化（2026-11-11）

旧链路：原生层每 80 毫秒检查鼠标 → Tauri 事件 → WebView → Tauri 请求 → Python/UIA → WebView → Tauri 高亮命令 → 原生四条边框。
更新后的悬停链路：原生层每 33 毫秒检查鼠标 → 最新坐标通道 → Python/UIA → 原生四条边框。
WebView 继续负责开始/取消、Ctrl 锁定后的完整属性与定位条件；连续悬停不经过 WebView。

- UIA 悬停使用 ElementFromPointBuildCache 和 FindAllBuildCache，把矩形、屏幕外状态、进程和运行时身份批量读取，避免逐个创建包装对象和重复读取属性。
  缓存请求只复用字段定义，每次悬停都重新获取当前元素和几何信息，不复用旧矩形。保留命中点下更细子控件的查找。
- 排除觅元自身时，先通过 WindowFromPoint/GetAncestor 找所属原生窗口，避免每次沿 UIA 父级逐层读取；仍检查实际元素进程。
- 悬停串行查询，只保留一个最新待处理坐标；旧会话、取消后的返回和较早序号仍由原生层拒绝。
  工作进程超时/退出继续走同一套重置和通知流程，不在钩子里调用 UIA。

本机可控 Windows 窗体、UIA 后端的测量（毫秒）：

| 测量 | 优化前 | 批量读取和 33 毫秒采样后 |
|---|---:|---:|
| Python 悬停识别中位耗时，20 次 | 23.82 | 6.93 |
| 鼠标移动到原生红框位置匹配，中位延迟，36 次 | 142.55 | 98.63 |
| 同一整链路测量的 P95 | 219.70 | 170.77 |

上述整链路结果来自仍经过 WebView 的中间版本，36 次均与按钮、输入框、文字、嵌套控件和禁用按钮的实际矩形一致。
最终版本进一步移除了悬停的 WebView 往返，其完整延迟尚未取得有效复测数据：复测时鼠标所在位置命中 Windows 锁屏界面，
没有命中测试窗体，36 次矩形比对均无效，不能据此报告最终延迟或识别失败。已观察到新链路返回并绘制原生边框，取消后可见边框数为 0。
这些测量不代表企业微信或所有 UIA 提供程序的速度；仍需要在解锁后的实际目标界面复测。

本轮前端 77 项、Python 桌面适配层 11 项通过（含两种后端、多屏负坐标、细控件矩形、失效候选和自身排除）；

### 异常提供程序的部分捕获保留（2026-11-11）

本次确认并修正两处错误处理：缓存悬停的子控件枚举/运行时标识读取异常会丢弃已取得的矩形；
完整捕获发现父级标识重复时直接抛错，会同时丢弃当前元素属性。
重复标识可能来自实际循环，也可能来自运行时标识缺失后的身份退化，不能仅据此断言目标软件的 UIA 父级一定循环。

- 悬停细化失败时保留当前命中矩形；缓存命中本身失败时改用普通 ElementFromPoint，仅读取当前几何信息。
  普通命中也失败时仍返回真实错误。两条路径都继续排除自身进程。
- 父级链重复、断开、父级读取失败或超过上限时保留元素属性和已读取层级，显示警告，locator 为空；不调用运行库生成不完整定位。
  所属窗口仍作为编辑范围保留，部分路径属性默认不勾选，避免无意导出仅定位窗口的条件。
- 没有候选 locator 的捕获不自动展开控件树，避免在成功展示属性之后再次触发同一层级异常。

前端完整 78 项通过，Tauri debug 程序重新构建并重启。
新增异常链测试涵盖循环、断开、父级读取失败和深度上限；悬停测试涵盖子控件读取失败、运行时标识读取失败、缓存命中失败和自身排除。

### 无 RuntimeId 的 MSAA 代理控件兼容与查询读取优化（2026-11-11）

实际样本为已打开渠成 ERP 的顶部“请假人员”按钮，使用用户提供的 请假人员.json。仅执行读取，未点击按钮或重启 ERP。
按钮经 UIA/MSAA Proxy 暴露，RuntimeId 为空、HWND 为 0；“快速访问”“首页”“Lower Ribbon”亦如此。
UIA 原生 CompareElements 确认这些是不同控件，真实父级链可到达主窗口。

修复独立运行库 desktop_automation/windows.py 的身份回退：可靠 RuntimeId 继续作为快速键；
UIA 缺失 RuntimeId 时，使用 UIAElementInfo 的原生 CompareElements 比较，PID 仅用于哈希分桶，不再用 (PID, 0) 代表控件。
Win32 继续使用进程与 HWND。运行时身份键不写入定位文件。
此规则同时用于查询去重、捕获细化、父级判重和控件树 token；定位生成增加循环及 128 层上限检查。

UIA 查询通过 FindAllBuildCache 批量读取每次过滤所需的名称、类名和 AutomationId。
精确标题预筛选保留所有有类名的控件，继续按 pywinauto rich_text 语义读取其 TextPattern，避免把 UIA Name 与文档文字混为一谈。
正则继续使用 match；每层仍查后代，匹配结果仍完整去重；返回前关闭过滤缓存，使后续操作读取当前属性。
提供程序拒绝缓存请求时退回原查询。悬停遇到空 RuntimeId 时正常保留命中几何，不再每次输出 NoneType 异常日志。

实测结果：
- 修改前按钮及父级 token 同为 1，父级会覆盖按钮。修改后分别为 1、2，按钮记录保持正确。
- 坐标捕获与查询为同一 UIA 元素，完整捕获不再警告，生成 5 层路径；6 个祖先/自身 token 互不重复。
- 新定位文件另存临时目录并重新加载后，匹配数为 1，原生比较仍为同一按钮，约 2.84 秒。
- 用户原文件连续 5 次查找均为 1 个。修改前约 3.39～3.69 秒，修改后本轮约 2.79～3.16 秒；跨轮存在桌面负载差异。
- 同进程分段对照 3 次：元素扫描原查询约 1.21～1.26 秒，批量查询约 0.96～1.03 秒，结果数量一致。
  查找所属窗口仍约 1.3～1.4 秒，本次没有持久缓存窗口或元素结果。
- 悬停几何 5 次约 14～45 毫秒，均为该按钮矩形且不再输出空 RuntimeId 日志；此数值不含完整红框绘制链路。

前端 78 项通过。Tauri debug 构建通过并重启预览程序。用户原定位文件未修改，未验证 ERP 重启后的定位稳定性。
